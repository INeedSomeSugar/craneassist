# v0.3 复核队列与原因记录

2026-10-27，本地工程增量。复核者可以先看需要特别核对的候选，并保存修改依据。原文、AI候选、人工判断及历史分别保留。

## 三分钟演示

按README创建DEMO并执行demo运行，再启动网页。默认按待审与提示优先排列，可切换“待复核”或“有重点提示且待复核”，也可按类别代码排列。

1. 打开合成例的B3，查看原文、类别边界和重点提示。
2. 展开“填写人工复核”，填写实际处理、复核人、意见和证据；修改或驳回时至少勾选一项原因。
3. 保存后核对当前人工判断、原因文字与待审数量；导出JSON或Markdown检查历史。合成演示中的判断仅用于功能验证。

现有六类原因：事故事实缺失或不符、类别或层级混淆、引文不足以支持判断、误用事后整改或建议、推理超出原文、其他原因。可多选，同一原因不重复；统计使用当前复核版本，不把历史版本叠加成多个人工样本。旧记录无原因时保持缺失，不追填推测。

## 提示如何产生

队列从既有候选的间接引文、相关但支持条件不足，以及类别边界／共享段落审计提示派生。先排未复核项，再按提示数及类别代码排序。提示数不是概率，也不说明有提示的候选更可能错误；它只决定阅读顺序。切换筛选不改变总候选数、标签或原文。

网页要求新修改／驳回记录原因；API允许缺省空列表以兼容旧客户端，并拒绝未知码与重复码。缺省记录会进入“未提供原因”数量，不能当作无错误。
